# Design: The agt inbox, a front door to every agent on every host

Generated by /office-hours on 2026-10-23
Branch: echo-review
Repo: robmorgan/agtd
Status: APPROVED
Mode: Startup (intrapreneurship: the founder is the sponsor and wants something usable this week)

## Problem Statement

The founder's words: "I want to redesign the `agt` command without any args. It should follow the claude design system, but the UX needs to be fundamentally improved. for instance I want to be able to easily start sessions locally, see all my configured hosts, attach to remote sessions, stop them, view, delete and create workspaces."

Bare `agt` today is the picker in `internal/cli/picker.go`: a filter box, up to eight session rows and a create row, drawn below the prompt, talking to one daemon. With `--host NAME` it shows that host's sessions but refuses to create there (the toast says to use `agt new -C DIR host/NAME`). Hosts are visible only through `agt hosts` and `agt ls --all`; workspaces only through `agt workspace add|ls|rm` and `agt new -w`. The screen answers "which session on this daemon" when the product's thesis is "which agent, anywhere, needs me".

## Demand Evidence

- The founder runs daemons on four machines (this Mac, a Linux devbox over Tailscale, two cloud droplets) and reaches them through the two-command path below every day. Observed friction with an existing workaround, not a hypothetical.
- The approved April 2026 design ("agentd Attention Inbox") specified this front door; its detection half shipped (OSC 7501 program status, `state.db` v6) and the screen never replaced the picker. The demand predates this session by six months.
- The trial prospect (Head of Infrastructure, author of pi-remote) built their own remote tool because ssh latency bugged them; a front door that cannot reach their devbox is the first thing they would see.
- Market signal: Anthropic shipped Agent View (`claude agents`, May 2026), a single-machine version of this screen. The grammar is now in every Claude Code user's hands.

## Status Quo

"They run `agt ls --all`, then type `agt attach host/name` by hand." Two commands and a retyped name, every time. `agt ls --all` waits for the slowest host (4 s cap) before printing anything. Remote creation means remembering `agt new -w WORKSPACE host/NAME` or a path as the other machine sees it, which is what sends the founder to ssh.

## Target User & Narrowest Wedge

The user is the founder, then the trial prospect on their devbox. The wedge, chosen knowingly as a 5/10 completeness shortcut (decision e87ca467): the multi-host attention inbox with Enter-to-attach, so the two commands become one keystroke. Ceiling: remote creation and workspaces stay in the subcommands. Upgrade trigger: the founder still drops to ssh to start work on a remote box, or the trial prospect asks where to start a session from the screen; then the create and workspace phases ship next.

## Constraints

- Pure-Go CLI: `internal/cli` never imports `worker`, `daemon` or `db`; it reaches state only through the protocol. No protocol change in phase 1, except one optional field: `KillSession.ExpectUID` under a new capability, so a remove from the inbox acts only on the incarnation its row showed; against an older daemon the inbox re-lists the host before sending and refuses if the UID changed (eng review D10).
- Inline rendering like Claude Code: no alternate screen for the inbox, grows to the rows it needs, clears on exit. Attach owns the alternate screen as today.
- The agtd brand system: graphite ground, grey dots, amber as the single signal hue, states named running / working / blocked / needs you / exited, no gradients. On this screen amber is reserved for what needs the user or marks where they are: the ⚠ glyph and message of a needs-you row, the ⚠ of a host in the strip that needs the user (unauthorized or key changed), the selected row's `▌` bar, the active input's `❯` glyph, and toasts. It is never decoration or a background wash. This is what the overlay already does with the same tokens (`overlayTheme`, 24-bit and 256-colour variants).
- Claude Code's grammar: one table, one input at the bottom, numbered choices, dim hint line, Esc stops nothing.
- A slow or dead host never stalls the screen; every host is listed with its state.
- Session names are unique per daemon only; row identity is host plus session UID.

## Premises

Agreed by the founder; premise 3 revised after the cross-model challenge.

1. Bare `agt` is the front door to every paired daemon, not one: it probes this machine and every host in `hosts.toml` in parallel, as `agt ls --all` does, and shows one list; `--host` only narrows it. Offline or unauthorized hosts appear as a line with their state, never as a stall.
2. The list is an attention inbox: needs-you first, then working and idle, exited last; each row's reason is the program's own status message; host is a dim column on the row, not a section header.
3. Agent View's grammar (one table, one input at the bottom, Space to peek, type to reply inline, Enter attaches, Esc leaves everything running) is the destination. Revised: the bottom input is a filter in release one; peek and inline reply are a named later phase gated on a timed trial, because what a reply means across Claude, Codex and pi is interaction design, not transport.
4. Lifecycle (attach, stop, remove, take over size) is a numbered per-row action menu on the same screen, like Claude Code's permission prompt, never a separate mode to find.
5. Starting a session is a where-plus-what flow: host (or auto), workspace or directory, agent, name. On a remote host a workspace is the only sane source of a directory, so workspaces appear inside the create flow with add and remove there; this ships after the inbox.
6. The existing code carries most of it: `hosts.go` probing and `allhosts.go`'s `hostSession` rows, the picker's rows and key decoder, the overlay's theme and renderer, the compose and submit-and-switch path, the workspace and kill requests.
7. Distribution is the existing `agt` binary through the release workflow and `install.sh`. Doing nothing keeps the two-command path and shows the trial prospect a picker that cannot reach their devbox.

## Landscape

Searched with category terms only. Session pickers are filtered lists with Enter to attach (tmux sessionizer and fzf, Zellij's session-manager). Agent managers add a per-row glyph (Agent Deck: ● running, ◐ waiting, ○ idle, ✕ error) and a preview of the latest output (Claude Squad); all are single-machine or escape to a hosted web dashboard (amux, Opcode). Agent View is "one table, one input at the bottom, every active session in a row": rows show whether the session needs input, its last response and when you last touched it; Space peeks, replies go inline, number keys answer multiple-choice questions, Enter attaches, Esc stops nothing. Single machine, Claude Code only.

Eureka: everyone builds the dashboard as a local table because the agent runs where the UI runs. agtd's daemon model breaks that assumption, and the pieces Agent View needs already exist in the protocol across hosts and across Claude, Codex and pi.

## Cross-Model Perspective

Codex (gpt-6.1-sol) cold read, from a structured summary only:

- Strongest version: "A terminal attention inbox for coding agents across every machine you use: open `agt`, see who needs a decision and why, and enter the right session immediately. Durable daemons make location incidental; Claude-style interaction makes the inbox familiar."
- Decisive answer: the status quo quote. "Build the shortest path from discovery to attachment; demand for peek, inline replies and workspace administration remains unproven."
- Challenged premise 3 as a first-release requirement. Evidence that would prove it: "in timed trials, the founder and prospect complete representative interventions faster with filter-and-attach, while peek/reply adds mode confusion or frequent fallback to attaching." Accepted: premise 3 was revised and the trial is the gate for phase 4.
- 48-hour prototype: replace the picker with the multi-host inbox; stream probe results as each host finishes (today `probeHosts` waits for all); reuse `hostSession` as the row model; preserve selection by host and UID across reorders; add an inbox ordering that separates working from idle and a summary fallback to `StatusMsg` (verified: `sessionSortBucket` ranks live sessions by attention level only); tests for duplicate names across hosts, selection surviving reorder, a dead host beside a usable one, and attachment routing. Skip peek, replies, menus, remote creation and workspaces.
- Recommendation: "Ship the multi-host filter-and-attach inbox this week because it removes the only demonstrated daily friction and tests whether the front door earns repeat use."

Where this design differs: Codex's prototype is approach A below; the founder chose approach B so the later phases have a home. Phase 1 is A plus the shared theme move, the streaming probes and the parity menu, which is why it is sized at about twice A (human ~1 week, CC ~2 days against A's ~3 days / ~1 day).

## Approaches Considered

### Approach A: Widen the picker (minimal viable)

Keep `picker.go`'s shape; swap its single `listSessions` for the host probes, make rows host+UID, build a client for the row's host on Enter, add a host strip, stream probe results. Effort S-M (human ~3 days, CC ~1 day), risk low. Rejected because the eight-row inline block has no room for the create flow, workspaces or peek, and the picker exits into attach so a detach drops you at the shell.

### Approach B: One inbox screen, phased (chosen)

See Recommended Approach.

### Approach C: The overlay is the front door (lateral)

Bare `agt` becomes `agt attach` with no session: the Ctrl-Y overlay opens over an empty screen, its switcher becomes the inbox, detach returns to it. Rejected because the overlay assumes an attached client, one host and a session's size; switching hosts means swapping connections inside attach's reconnect and frames logic, and its centred box (max 100×26) is not a front-door layout.

## Recommended Approach

Approach B: a new `internal/cli/inbox.go` replaces the picker as bare `agt`. Wireframe: `~/.gstack/projects/robmorgan-agentd/designs/agt-inbox-wireframe-20261023/sketch.html` (screenshots `p1.png` inbox and first-300 ms, `p2.png` actions and new-session steps, `p3.png` peek and first run; `sketch.py` regenerates them with every column padded by construction).

### The screen

Inline below the prompt, like Claude Code: no alternate screen, grows to the rows it needs, cleared on exit. The whole block (header, the host strip as wrapped, the rows, the `+` row, a toast if any, the input box and the hint line) is capped at the terminal height minus one, since `drawPicker`/`clearPicker` redraw by moving the cursor up and a block taller than the screen would corrupt it; the row list takes what the fixed parts leave and scrolls within that, keeping the selected row visible. Top to bottom:

1. Header: `agtd` in bold; right-aligned counts (`2 need you · 3 working · 1 idle · 1 exited`).
2. Host strip: one entry per host, `local` first then `hosts.toml` order: name, glyph, session count, latency. ● (ok) online, ◌ (quiet) still being asked, ○ (quiet) offline or not running, ⚠ (signal) unauthorized, with the fix `agtd remote authorize FINGERPRINT` to run on that host, or key changed, with `agt host rm NAME` and adding the host again; `agt host info NAME` shows the error itself. The strip wraps onto a second line past the width.
3. Rows, sorted needs-you first, then working, running, idle, then exited and failed: leader (two cells; the selected row is raised on `line` with an amber `▌` bar, as in the overlay), state glyph (⚠ signal needs you, ● ok working or running, ● quiet idle, ○ quiet exited, ✖ failed), name (bold when selected, muted when exited), host (muted, 7 cells), agent (muted, 6 cells), state word with elapsed time (`blocked 4m`, `waiting 12m`, `working 62%`, `working`, `running`, `idle 38m`, `exited (1)`), the program's own message (`StatusMsg`, amber when attention is action, text otherwise, empty for a non-reporting program), and how long the session has run at the right edge (quiet). Below 90 cells the agent column goes first, then the message truncates; below 60 the host folds into the name as `host/name`.
4. `+ new session` row, last, with the typed name when the filter matches no session.
5. The input: a bordered box with rounded corners in `line`, a `❯` glyph (amber when the input is active) and a block cursor; placeholder "Filter, or name a new session".
6. One hint line: `↑↓ choose · enter attach · tab actions · n new · esc quit · ? keys`; keys in text, labels muted, separators quiet.

Toasts (an error from a daemon, "removed session x") appear above the input in amber for ten seconds or until the next key. Every failed inbox action (remove, re-probe, create, and from phase 2 stop, take over size and a failed attach) is a toast with the error text and the inbox stays running with the row unchanged; only a failure to read the terminal or to draw exits bare `agt` (eng review D6).

### States

One vocabulary for the brand's five words, the record's statuses and activities, the glyphs, the sort and the header. The brand list (running / working / blocked / needs you / exited) is extended by waiting, idle, starting, failed and lost, which the record already distinguishes.

| Record | Glyph | Row word | Sort bucket | Header count | Enter |
|---|---|---|---|---|---|
| running or creating, attention action (blocked or waiting) | ⚠ signal | `blocked 4m` / `waiting 12m` | 1 needs you | need you | attach |
| running, activity working | ● ok | `working` / `working 62%` | 2 working | working | attach |
| running, activity unknown (no status reported) | ● ok | `running` | 3 running | working | attach |
| creating | ● ok | `starting` | 3 running | working | attach (waits for the PTY as today) |
| running, activity idle | ● quiet | `idle 38m` | 4 idle | idle | attach |
| exited | ○ quiet | `exited` / `exited (1)` | 5 exited | exited | actions |
| failed | ✖ red (terminal default, as the picker) | `failed` | 6 failed | exited | actions |
| unknown_recovered (lost) | ○ quiet | `lost` | 7 lost | exited | actions |

A running row at attention notice (done, info-level events) keeps its activity word and sorts by it; only action-level attention makes a needs-you row, as `rowIcon` does today.

### Keys

- Typing filters by name, host, agent, state and message (`matchesQuery` over the row's search text); a `host/` prefix narrows to that host, the way `agt attach sfo/auth` addresses a session. `--host NAME` opens with that prefix applied and locked (phase 1 commits to the lock, which is what today's picker does with `--host`).
- Letter keys are commands only while the filter is empty and no menu is open: n (new session), r (re-probe every host now, eng review D4), ? (full key list in place of the hint line), and in phase 5 h (focus the host strip). Consequence: a filter cannot start with n, r, h or ?. For a host whose name starts with one of those letters, type a space first (space is never a command in phases 1 to 3, so it enters the input; matching trims it, as `matchesQuery` does today) or open with `--host NAME`. Once the filter holds text, every printable character including space goes to the input, and the hint line changes to `↑↓ choose · enter attach · tab actions · esc clear`. Space in phase 4 peeks only while the filter is empty. Tab, Enter, Esc, the arrows and digits inside an open numbered menu are commands whatever the filter holds; a digit with no menu open is filter text.
- While a menu or confirmation is open, printable keys and pastes are ignored, as the picker's action and confirm modes ignore them today, with two exceptions: digits choose a menu item, and y and n answer a confirmation as the picker's delete confirm takes them. The hint line then reads `↑↓ choose · enter select · esc back` (`enter confirm · esc back` on a confirmation), matching the picker's "Esc goes back" lines; ? lists these too.
- ↑↓ move; the selection follows the row's host+UID across refreshes and reorders.
- Enter on a running or starting row attaches (a client for its host, `attachSessionUID`). Enter on an exited, failed or lost row opens the row's actions (remove in phase 1; diff and history join in phase 2), as today's picker does for a non-running session, since attaching to it would fail at the daemon. Enter on the `+` row opens the new-session flow.
- Tab or → expands the row's actions (attach and remove in phase 1; the full menu in phase 2). The menu lists attach only for a running or starting row, matching Enter's rule and the picker's `actions`, so a non-running row's phase 1 menu is remove alone. Esc works innermost-out: it cancels an open confirmation (returning to the row's menu, as today's picker returns to its actions), else collapses an open menu, else clears a non-empty filter, else quits with everything running. A typed filter stays as it is while a menu or confirmation is open.
- Digits choose in any open numbered list, as in Claude Code's prompts.

### Model

- `hostSet` (new, in `hosts.go`): the probes of `probeHosts` delivered incrementally over a channel as each host answers, re-probed on a ticker (the picker's 200 ms refresh for the local daemon; every 2 s for remote hosts, so a remote round trip is never paid twenty times a second), with `probeTimeout` per host. Concurrency rules, per the repo's ownership requirement: one goroutine per host owns that host's probing and sends each result as an immutable snapshot on the set's channel, never touching it again, while the UI goroutine owns the map of latest snapshots and all rendering state, so no field is shared between goroutines (eng review D5); at most one probe is in flight per host, and a tick that arrives while one runs is skipped; a probe that fails or a connection that is lost marks the host with its state and is redialed with exponential backoff, 2 s doubling to a 30 s cap, reset when the host answers or when r re-probes every host now (eng review D4); the inbox owns the set through a context, and cancelling it ends every goroutine and closes every stream before the inbox returns. `agt hosts` and `agt ls --all` keep their blocking call over the same code.
- Bare `agt` ensures the local daemon is running before the first probe, as the picker and `listAllSessions` do (`prepareDaemon`), since `probeHosts` by itself never starts it; a cold start therefore shows `local ◌ starting` until the daemon answers, and the 300 ms criterion below applies when it is already running. A view locked by `--host NAME` probes only that host and never starts or touches the local daemon, as `agt --host X` behaves today; its strip shows that host alone (eng review D3).
- Rows are `hostSession` (`allhosts.go`): host name, Welcome, record. One control stream per online host is kept open while the inbox runs, owned by the `hostSet`, for listing and for kill and remove. An attachment never shares it: attach gets its own `client` for the row's host, because attach's reconnect path owns and replaces the client's connection. In phase 1 the inbox cancels its `hostSet` (closing every stream) before exiting into attach; in phase 2 it pauses the set (cancels it) for the attachment's duration and starts a fresh one on return, so probes never compete with the attach stream on a connection.
- Actions never block the UI goroutine: remove, create and re-probe (and in phase 2 stop, take over size, and the rest) run on a goroutine owned by the inbox's context, the row shows a pending word (`removing…`, `starting…`) until the result arrives on the UI channel as a row change or a toast, and a second action on a pending row is refused with a toast (eng review D9). Requests take the caller's context (context-taking forms of the request helpers); actions run on their own context, separate from the hostSet, so an attach does not cut them; before an attach or a quit with actions pending the inbox shows "finishing removing NAME…" and a second Esc abandons; an action whose answer is lost toasts "result unknown, refreshing" and re-probes its host instead of keeping the row unchanged (eng review D12).
- Ordering: a new `inboxSortBucket` (needs-you, working, running, idle, exited, failed, lost) replaces `sessionSortBucket` everywhere, the inbox, `agt ls` and `agt ls --all` alike, in phase 1 (eng review D16).
- Rendering: the overlay's `line`/`span` renderer and `overlayTheme` move to a shared file (`theme.go`), so the inbox and the overlay are the same vocabulary; the picker's `drawPicker`/`clearPicker` inline redraw stays the drawing loop.
- The attach loop returns to the inbox after a detach (phase 2): `runRuntime` loops until Esc or an attach ends by the session exiting with the user choosing to leave. When launched from the inbox, attach enters the alternate screen itself before its repaint, leaves it on return without the detach clear, and suppresses its "attached to" and session-end lines (a flag on the client the inbox sets), so the terminal restores the primary screen with the inbox block intact and the inbox redraws over it; plain `agt attach` is unchanged (eng review D2, mechanism revised by D11).

### Phases

1. **Inbox with attach** (the wedge; human ~1 week, CC ~2 days). Header, host strip with streaming probes, rows, filter, Enter attaches on any host (a non-running row opens its actions), `+ new session` with today's local agent chooser and current-directory creation, Esc quits. In a view locked by `--host NAME` the `+` row keeps the picker's toast (`agt new -C DIR host/NAME`) until phase 3, rather than creating a local session the lock would hide. Parity with the picker: Tab opens a two-item menu, attach and remove, where remove is `KillSession` with `Remove` sent through a client built for the row's host (the same per-host client Enter needs to attach), confirmed on the line (Enter to confirm · Esc). The effort above includes that menu. Replaces `picker.go`; `picker_test.go`'s rendering and key tests move with it. Phase 1 also carries (eng review, carried forward under approved contracts): `renderSessionList`, `listLayout` and `fitColumns`, which `agt ls` and `agt ls --all` draw with, move from `picker.go` to `display.go` with `TestSessionList*`; the renderer moved to `theme.go` measures terminal cells with `uniseg` instead of runes, so wide characters in status messages never wrap a row (eng review D14; `agt ls` keeps its rune path), and gets `theme_test.go` (truncation including wide characters, padding, the empty theme); the block cap re-reads the terminal geometry on every draw and on SIGWINCH and clears then redraws when it shrinks; and README.md (the picker at line 189), ARCHITECTURE.md (lines 27, 694, 753, 1057) and ROADMAP.md (line 863) are updated from "the picker" to the inbox in the same PR.
2. **Row actions and the loop.** Tab's menu grows a detail line (`host/name · cwd · agent · who is attached and who owns the size`) and the full numbered actions: attach, stop, remove, take over size, diff (opens `agt diff` output in the pager), and for a non-running row history too. Stop and remove confirm on the same line (Enter to confirm · Esc). Detach returns to the inbox.
3. **New session anywhere.** n or Enter on `+`: Where? (local, each online host with load and latency, offline hosts listed but unselectable, auto) → Where on the host? (for local, "this directory" first, then its workspaces, since local workspaces exist for `agt new -w` too; for a remote host, its workspaces; on both, "a directory" typed as the host sees it, "+ add a workspace" with name and path stored on that host, x removes the chosen workspace after a confirm) → Agent? (the host's Welcome agents, its default first, codex showing its model) → Name (blank picks one). Enter starts and attaches; Ctrl-Enter starts and stays in the inbox. This replaces `agt workspace add|ls|rm` for the interactive case; the subcommands stay for scripts.
4. **Peek and reply**, gated on the timed trial (see Success Criteria). Space shows the last twelve rows of the session's screen under its row, fetched through the existing snapshot path on a short-lived attach stream that does not take the size; for a blocked Claude Code session that is the permission prompt, so 1/2/3 answer it as a raw `SendInput` of the digit (not `Compose`, which pastes the data and then sends Enter, and Claude Code's numbered prompts act on the digit alone); the input becomes "Reply to host/name", Enter sends the typed reply through `SendInput` with `Compose`, Ctrl-Enter sends and attaches.
5. **Host health.** h focuses the strip; Enter on a host shows `agt host info` inline (latency, version, CPUs, memory, agents, sessions) and, for an unauthorized or key-changed host, the fix.

### Empty and edge states

- First run: `local ● 0`, "No sessions yet.", the `+` row selected so Enter starts an agent here, one line on pairing a devbox (`agtd remote pair` there, `agt host add NAME ADDRESS --code CODE` here).
- All hosts offline: the strip shows each state; the list shows local rows or "Nothing reachable."
- Duplicate names across hosts: both rows show; the filter `host/` prefix separates them; attach goes by host+UID.
- A session that exits while selected keeps the selection (its row turns to exited); a removed one moves the selection to the next row.
- Narrow terminals: columns drop as above; below 40 cells the inbox prints the rows it already holds for its own scope (the locked host only under `--host NAME`) in the `agt ls` row format and exits with a one-line hint; it never calls `listAllSessions`, so the `--host` lock holds at every width (eng review D15).
- `NO_COLOR` or `TERM=dumb`: the overlay's empty theme, glyphs stay.

## Open Questions

1. Should the session's directory be a dim column at 120 cells and wider? Today it is only in the row's detail line and in peek. The founder approved the wireframe without it; revisit after a week of use.
2. Does the host strip belong above the list (as drawn) or below it, next to the input? Above answers "is everything reachable" first; below keeps the eye on rows.
3. Resolved by eng review D16: `agt ls` adopts `inboxSortBucket` in phase 1, so the inbox and `ls` share one ordering.
4. Peek's data path: a short-lived attach stream that declines size ownership, or a new read-only screen request. The former needs no protocol change; the latter is cleaner. Decide when phase 4 is unblocked.
5. Phase 1 locks `agt --host NAME` to that host. Revisit after a week of use whether a prefilled, clearable `host/` prefix would serve better, now that one screen can show every host.

## Success Criteria

1. Phase 1: opening `agt` and reaching a named agent on another host takes one keystroke after typing part of its name, with no host name retyped; with the local daemon already running, local rows appear within 300 ms while remote hosts are still being asked (a cold start adds the daemon's start time, shown as `local ◌ starting`); a dead host never delays the list past its own entry.
2. The founder stops using `agt ls --all` followed by `agt attach host/name` within a week of phase 1 shipping (checked by habit, not by telemetry).
3. Phase 4 gate: a timed trial with the founder and the trial prospect, ten representative interventions each (answer a permission prompt, answer a question, stop a session), filter-and-attach versus peek-and-reply. Peek and reply ship only if they are faster on the median intervention and neither user falls back to attaching more than twice in ten.
4. Tests (in the inbox's successor to `picker_test.go`, whose mode tests are the place for the Esc order): duplicate names across hosts; selection surviving a reorder; a dead host beside a usable one; attach routed to the right host; remove confirmed and routed to the row's host; the 96-, 80- and 60-cell layouts and the below-40-cell fallback to `agt ls --all`; first run; every key in each hint line; Esc leaving every session running; the innermost-out Esc order (confirmation, menu, filter, quit) with the filter kept across a menu; the `--host NAME` locked view and its `+` toast; Enter on a non-running row opening actions; letter commands only with an empty filter and the leading-space escape; the selection rules when the selected session exits or is removed; `NO_COLOR` and `TERM=dumb`; the state table above, one case per row; the block cap at the terminal height.

5. Regression contract for replacing the picker (eng review D8). Preserved: typing filters; a running row reaches attach; remove asks for a confirm; create offers the agent chooser and takes the typed name; Esc quits with everything running; attention-first order; `agt ls` and `agt ls --all` output byte-identical except row order, which follows `inboxSortBucket` (eng review D16). Intentional changes: Enter on a running row attaches directly (the menu is under Tab); rows from every host with a host column; working and idle separated; Esc innermost-out; n, r, ? and h are commands on an empty filter; the placeholder reads "Filter, or name a new session"; the legend row is dropped (the state table and glyph colours replace it); the 8-row cap becomes the height cap. Assertions: the 14 picker tests move to `inbox_test.go` and pass with host `local`, with `TestPickerActionMenu`'s Enter path, `TestPickerLegend` and `TestPickerQueryLine`'s placeholder rewritten to the new behaviour and saying so; `TestSessionList`, `TestSessionListShowsAttention` and `TestSessionListWithHosts` pass with only their expected order updated where working and idle sessions are mixed, and `TestOrderedSessions*` (display_test.go:103, 174) are rewritten for `inboxSortBucket`; `TestInboxEndToEnd` (eng review D7, fixture revised by D13: two daemons, the second paired as `dev`, each with a session named `demo`; both rows show, `dev/` narrows, Enter attaches to dev's, Tab → remove → confirm removes dev's while `local/demo` keeps running, Esc leaves sessions running) asserts the new Enter and the Esc guarantee.
